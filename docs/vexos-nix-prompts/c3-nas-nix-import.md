# Prompt C3 — conditionally import `/etc/nixos/nas.nix`

Paste everything below the line into Claude in `~/Projects/vexos-nix`.

---

Task: add an optional host-local file `/etc/nixos/nas.nix` to the server and headless-server roles,
wired exactly like `storage-pool.nix` / `zfs-pools.nix`. Follow your CLAUDE.md workflow.

## Background
`nas.nix` will be generated by the vexnas web UI. It is pure data setting existing `vexos.server.*`
options (and, after later changes, `vexos.server.nas.shares`). When it is absent nothing changes.

There are two import paths and **both** must be updated:
1. `template/etc-nixos-flake.nix` (the `/etc/nixos/flake.nix` wrapper hosts actually use through
   `just rebuild`): add `nasFile = ./nas.nix; hasNas = builtins.pathExists nasFile;` next to
   `zfsPoolsFile`, with a comment, and append `++ lib.optional hasNas nasFile` in
   `mkServerVariant` and `mkHeadlessServerVariant` only (not desktop/htpc/stateless/vanilla).
2. Repo `flake.nix` (`mkHost` path): add
   `nasModule = let p = /etc/nixos/nas.nix; in if builtins.pathExists p then [ p ] else [];`
   beside `storagePoolModule` (same explanatory comment style) and append it to
   `roles.server.hostLocalModules` and `roles.headless-server.hostLocalModules`.

Also:
- `template/server-services.nix`: add a short comment that `/etc/nixos/nas.nix` is generated and owned by
  the vexnas UI (`vexos.server.vexnas.enable`) and should not be hand-edited alongside it.
- Update any doc/comment lists enumerating host-local files, and `scripts/preflight.sh` if it checks the
  template for expected pathExists entries.

## Important constraint to document in your spec
Existing hosts have an older *copy* of `template/etc-nixos-flake.nix` in `/etc/nixos/flake.nix`, so they
will silently ignore `nas.nix` until that file is refreshed. Check whether the repo already has a
mechanism to refresh the wrapper (look in justfile / vexos-updater / installer scripts); report what the
operator must do, and if a safe, existing recipe exists mention it. Do not invent a new self-modifying
mechanism. vexnas will detect an outdated wrapper by grepping it for `nas.nix`, so keep the token
`nas.nix` literally present in the wrapper.

## Constraints
Never run `nix flake check`, `nixos-rebuild switch/boot`, or any git write. Validate with
`nix flake show --impure` and per-target dry-build (server-amd, headless-server-amd) as your CLAUDE.md
prescribes, with and without a stub `/etc/nixos/nas.nix` containing `{ ... }: { }`.

## Done when
Both server roles evaluate identically with no `nas.nix`; with a trivial `nas.nix` present it is
included in both import paths; no other role is affected.
